# Развёртывание TechMES

Maintenance находится на Primary, 192.168.1.118. Secondary приложений — 192.168.1.132.
Компьютер 192.168.1.131 относится к PostgreSQL; этот сценарий не меняет БД или репликацию.

## Разработка: General → Deploy

1. В Settings → Server выбрать настоящий TechMES.sln и перезапустить Maintenance.
2. Запустить Maintenance от администратора. На машине сборки нужен .NET SDK 10.
3. Нажать Deploy all. Сначала проекты собираются в отдельную папку. При ошибке сборки службы продолжают работать.
4. После успешной сборки установщик проверяет пути и файлы, делает резервную копию, останавливает Web → Calc → Runtime, заменяет файлы и запускает Runtime → Calc → Web.
5. Ожидается `Deploy all finished successfully`. Существующие appsettings*.json сохраняются побайтно.

Deploy all не обновляет работающую Maintenance. На первой локальной установке её настроенные source-appsettings копируются только в ещё не установленную службу.

## Общий пакет для двух серверов

1. Рядом с Deploy all нажать «Создать архив». Выбрать локальную папку. Будет создан автономный ZIP win-x64 с Runtime, Calc, Web и Maintenance. Службы при сборке архива не останавливаются.
2. Открыть отдельное меню Deployment. Выбрать ZIP.
3. Заполнить оба профиля: компьютер, фактическая папка установки, сетевая папка доставки, локальный URL проверки Runtime, компоненты.
4. Primary: компьютер 192.168.1.118, путь по текущей установке, обычно C:\TechMES. Secondary: 192.168.1.132, обычно D:\TechMES. Путь профиля должен совпадать с установленными службами.
5. Maintenance по умолчанию выбрана только для Primary. Для её обновления приложение на целевом сервере нужно закрыть.
6. Нажать «Подготовить комплект». В новой локальной папке появятся:
   - TechMES_Deployment.zip — один и тот же архив для обоих серверов;
   - Deploy-Primary.ps1;
   - Deploy-Secondary.ps1.
7. Обе копии скриптов также включены внутрь общего ZIP. После изменения параметров установки комплект нужно подготовить повторно.
8. Send около сетевого пути копирует общий ZIP и подходящий скрипт в новый подкаталог назначения. Используется текущий доступ Windows. Удалённого запуска, WinRM, смены учётной записи и задач SYSTEM нет.
9. При отказе Send открыть папку комплекта и скопировать ZIP со скриптом вручную. Ошибка доставки не удаляет локальный комплект.

## Запуск на Secondary

1. Скопировать TechMES_Deployment.zip и Deploy-Secondary.ps1 в одну папку на 192.168.1.132.
2. В PowerShell от администратора, открытом в этой папке, выполнить:
   `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Deploy-Secondary.ps1`
3. Скрипт проверит компьютер и версию пакета, распакует ZIP в отдельную рабочую папку, проверит SHA256, создаст резервную копию и обновит выбранные компоненты.
4. Ожидается `SUCCESS. Selected services are running. Existing appsettings files were preserved.` Runtime может быть Active либо Standby.
5. При сбое обновления установщик возвращает прежние файлы и исходные Running/Stopped состояния. Если откат не завершился, это явно отмечается `ROLLBACK INCOMPLETE`.

Для Primary без исходников выполнить аналогично Deploy-Primary.ps1. Скрипт также умеет запросить повышение прав при обычном запуске. Скрипты можно запускать из полностью распакованного ZIP; лежащий рядом общий ZIP вручную распаковывать не требуется.

## Настройки и журналы

- Профили Maintenance: %ProgramData%\TechMES\Maintenance\package-deployment.json.
- Журнал каждого запуска: %ProgramData%\TechMES\DeploymentRuns\<запуск>\deployment.log.
- Резервные копии: %ProgramData%\TechMES\Updates\<запуск>.
- appsettings*.json, локальные данные и закрытые сертификаты не включаются в пакет и не заменяются им.
- На новом сервере заранее нужны собственные appsettings.json в папках выбранных служб. Если служба ещё не зарегистрирована, скрипт создаст её после проверки конфигурации. Существующие учётные записи служб не меняются.
- Неизвестные пользовательские файлы не удаляются. При обновлении Maintenance удаляются устаревшие Tools/Deploy-TechMESSecondary.ps1 и Tools/Run-TechMESUpdate.ps1.
- PostgreSQL и его службы этим установщиком не управляются.
