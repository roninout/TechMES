# TechMes Host: первый этап

Windows name: `TechMES.Host`. Display name: `TechMes Host`. Папка: `<InstallRoot>\Host`.

Этот этап только наблюдает за локальным WEB. Он не назначает IP, не меняет Firewall, Runtime, Calc или PostgreSQL. `SharedAddressEnabled=true` намеренно блокирует запуск: передача общего IP будет отдельным этапом.

## Установка

В Maintenance → Services появилась отдельная строка Host и кнопка «Установить и запустить TechMes Host». Старый maintenance.settings.json удалять не нужно: строка добавляется при загрузке и не дублируется.

Проверьте корень установки перед нажатием. На ПК разработки кнопка собирает только Host, используя существующий поиск SDK; службы продолжают работать. На сервере без исходников выбирается новый автономный ZIP TechMES с компонентом `host`. SDK на целевой машине не требуется.

При первом запуске кнопка создаёт только отсутствующий `Host/appsettings.json`, используя локальный WEB Health URL из Maintenance. Существующие настройки не заменяются. Установка выполняется общим транзакционным updater только для Host. Автозапуск — Automatic. Повторное нажатие для установленной службы запускает её и проверяет health без повторной публикации.

Для обновления из архива в Deployment добавлен флажок Host. Он выключен в старых профилях. Перед первым пакетным развёртыванием Host используйте кнопку установки, чтобы подготовить локальную конфигурацию. Deploy all из исходников обновляет Host, если служба уже установлена.

## Диагностика

- `http://127.0.0.1:5116/api/health` — liveness Host, HTTP 200 при доступном контроллере.
- `http://127.0.0.1:5116/api/host/status` — компьютер, экземпляр процесса, Observer, состояние и время проверки WEB.
- `http://127.0.0.1:5116/api/health/ready` — HTTP 200 только при свежем подтверждении WEB; иначе 503.

API первого этапа по умолчанию слушает только IPv4 loopback; входящий Firewall не открывается. Доступ к Runtime API Host пока не нужен. Изменения конфигурации применяются после перезапуска службы. Windows Events → Application содержит события службы.

Проверка: остановить только WEB, убедиться, что Host остаётся RUNNING и `/api/health` возвращает 200, а `/api/health/ready` — 503; запустить WEB обратно и дождаться 200 ready. Проверять во время согласованного окна: остановка WEB прерывает браузерные сессии.

Общий URL и аварийный захват IP этим этапом не реализованы. Следующий этап: проверка статического интерфейса, свободного IP и согласованная передача адреса с журналом операции.
